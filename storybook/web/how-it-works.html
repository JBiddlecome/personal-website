How the agents make a book

Seven roles hand work to each other in a fixed order, run by an orchestrator (plain code) that saves a checkpoint after every step, tracks the cost of each agent, and stops whenever you need to approve or decide something. Every handoff is a schema: a fixed shape the next step can rely on.

Claude agent (judgment) Gemini image model (drawing) Plain code (rules, no AI) You decide Runs in parallel

1Your request

You

You fill in the form. The server checks it against the request schema before anything is spent.

InSubject, reader age, story type, style, number of pages
OutBookRequest, the one source of truth every agent receives

2Researcher

Claude Opus 5.5 + web search

The one true looping agent. It decides what to search for, reads the results, and saves facts one at a time with a tool our code runs. Our code rejects near-duplicate facts and tells it to find a different one.

InSubject, reader age, any direction you've given
Out8–12 kid-friendly facts, each with its source link

Loop: search → save_fact → read result → repeat, up to 15 turns

it calls ask_for_direction (subject unclear or unsuitable), or finds fewer than 5 reliable facts

3Outliner

Claude Opus 5.5

Plans the book page by page and builds the plot around two or three of the real facts. Writes a precise look for each character, which later keeps the pictures consistent.

InRequest, research, your direction or change notes
OutOutline: title, one-line story, theme, setting, characters + appearance, what happens and what to picture on each page

it fills in its needs_direction field (the request can't become a good book as given)

4Approve the outline

You · always

The cheapest moment to change course: nothing has been written or drawn yet.

You canApprove · ask the Outliner for changes (back to step 3) · cancel
OutAn approved outline

5Writer ⇄ Editor

Claude Opus 5.5 (both)

The Writer drafts the words for every page. A separate Editor, which never sees the Writer's instructions, checks a 7-point list (age fit, read-aloud rhythm, story, accuracy against the research, consistency, safety, your direction) and tags each issue must fix or nice to have. Code, not the model, approves the draft when there are no must-fix issues.

InRequest, approved outline, research, your notes
OutPage-by-page text + the Editor's last review

Loop: draft → review → revise with notes, up to 3 rounds

the Writer and Editor still disagree after 3 rounds

6Approve the text

You · always

You see the text and the Editor's notes. Edit any page yourself, or send it back.

You canEdit pages and approve · ask the Writer for changes (back to step 5) · cancel
OutThe final text, locked before any money is spent on pictures

7Art Director

Claude Opus 5.5

Chooses one art style for the whole book and writes a scene for each picture: who's in it, what they're doing, framing, mood, and room left for the words. Never asks for lettering.

InRequest, outline (character looks), final text
OutArt plan: style paragraph, character-sheet scene, cover scene, one scene per page

8Illustrator: character sheet

Gemini 3.1 Flash Lite Image

Draws every character side by side. Runs alone, first, because every other picture copies from it. The Illustrator is plain code calling Gemini: it makes no decisions, so it isn't an agent.

InStyle + character descriptions (added by code, identically every time)
OutThe reference picture used for every page

Art Reviewer

Claude Haiku 5.5 · vision

Looks at each new picture next to the character sheet, with the whole story for context (so a hat that's lost in the story isn't flagged as a mistake). Checks characters, scene, no lettering, nothing scary. Small counts and poses are only "nice to have". Uses the cheapest Claude model because it runs about 20 times per book.

InCharacter sheet, new picture, art direction, whole story, your notes
OutWhat it sees + must-fix / nice-to-have issues

a picture still has must-fix issues after 2 redraws, or Gemini returns no picture

10Decide on flagged pictures

You · only if needed

Each flagged picture is shown with the reviewer's reasons. Often the reviewer is being strict and the picture is fine.

You canAccept it · redraw it with your own instructions (back to step 9 for that picture only)
OutA complete set of pictures

11Assembler

No AI · pdfkit

Lays out a 10 × 10 inch book: title cover, a page per spread with the picture above and the words below (the font shrinks just enough to fit), and "The End". Page layout is a rule, so it's code: instant, free, and the same every time.

InFinal text, all pictures
OutThe PDF, saved with the book

Rules the design follows

  • Schemas for anything that must be exact; prompts for preferences. Every handoff above is a fixed shape.
  • Code makes the decisions: approvals, retries, limits and when to stop for you.
  • A reviewer is only as good as its context: the Editor gets the research, the Art Reviewer gets the whole story.
  • Fix repeated failures upstream: the Writer avoids things pictures can't show (counting, flying backward).
  • AI for judgment, code for rules: only the Researcher loops on its own; the Illustrator and Assembler aren't agents.
  • Never pay twice: every step's result is saved, so a stopped book resumes from its last checkpoint.
